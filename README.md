## 📋 Curriculum

### Day 2: Installation and DBMS Fundamentals
- **File Management System (FMS) vs Database Management System (DBMS)**
  - Key differences in data redundancy, security, and data sharing
  - Advantages of DBMS over traditional file systems
  
- **Core Concepts**
  - **Data**: Raw facts or figures without context (Example: 101, Ekantha, 600000)
  - **Field**: Smallest unit of data in a database (column/attribute) (Example: emp_id, emp_name, emp_salary)
  - **Record**: Collection of related fields (row/tuple) (Example: 101, Srirama, 60000)
  - **Database**: Organized collection of related records stored together
  - **DBMS**: Software for creating, storing, retrieving, updating, and managing databases

## 🔑 Key Takeaways

### DBMS Advantages over FMS
✅ Reduced data redundancy  
✅ Easy maintenance and updates  
✅ Strong security mechanisms  
✅ Multi-user support with simultaneous access  
✅ Supports relationships between tables  
✅ Built-in backup and recovery features  
✅ Scalable for applications of all sizes  

## 💡 Quick Reference

| Aspect | File Management System (FMS) | Database Management System (DBMS) |
|--------|-----|------|
| Data Redundancy | High (duplicate data) | Reduced |
| Maintenance | Difficult to maintain and update | Easy to maintain and update |
| Security | Limited | Strong security mechanism |
| Data Sharing | Difficult | Multiple users can access simultaneously |
| Relationships | No relationship between files | Supports relationships between tables |
| Backup & Recovery | Difficult | Provides backup and recovery features |
| Scalability | Suitable for small applications | Suitable for small, medium, and large applications |

## 📊 Data Hierarchy in DBMS

```
Database (Organized collection of related records)
    ↓
Table/Record Set (Collection of related records)
    ↓
Record/Row (Collection of related fields)
    ↓
Field/Column (Smallest unit of data)
    ↓
Data (Raw facts/figures)
```
